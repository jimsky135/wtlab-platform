# 一、已確認方向

## 1. 品牌定位

| 角色 | 定位 |
|---|---|
| **輪椅哥** | 品牌 IP 與視覺主角 |
| **輪椅流** | 核心理念——強調現實問題、韌性、容錯與持續校正 |
| **WTLab** | 輪椅哥的工具平台，承載實際工具與成果 |
| **創作者本人** | 提供真實經歷與個人風格，**但不把 WTLab 改成個人履歷網站** |

## 2. 首頁調整方向

- 從**工具陳列站**轉型為**輪椅哥的品牌入口**。
- 恢復早期小卡延續而來的詼諧、自嘲與漫畫風格。
- 可以大膽帶入創作者的個人語氣與特色。
- **「帶你飛，保證摔不死！」** 作為既有品牌精神。
- 協作理念透過角色、故事與成果呈現，**不另行包裝成 AI 教學平台**。

## 3. 內容與入口關係

| 內容 | 角色 |
|---|---|
| **漫畫** | 主要品牌內容，以生活白話與日常故事為主 |
| **輪椅工具** | WTLab 的核心實用成果 |
| **Blog** | 與漫畫互相導流 |
| **Podcast《行者自語》** | 輔助內容，可在網站提供播放，**不作為首頁主角** |

## 4. 工具區邊界

- 首頁可以大幅調整視覺個性。
- **進入工具區後，沿用現有專業、清楚的設計調性。**
- 保留七項 Instruments 的可發現性。
- 首頁應提供 Integrated Workspace 入口，並**如實標示其目前狀態**。
- **不因首頁轉型而重做工具介面或計算邏輯。**

# 三、前一輪的資訊順序構想（部分被本輪調整）

同日稍早記錄的版本，主張把首頁排成：

```
品牌定位 → 成果／方法雙入口 → 實際成果 → 協作案例
```

| 區塊 | 本輪之後是否仍成立 |
|---|---|
| 01 · 第一眼：品牌定位與主要行動 | **仍成立**，語氣改為輪椅哥的詼諧、自嘲風格；**具體入口待決**——不預設一定是兩個按鈕 |
| 02 · 雙入口（使用成果／探索方法） | **部分調整**——「探索方法」不再是獨立的方法論入口，改由角色、故事與成果承載；不做成 AI 教學平台 |
| 03 · 真正的成果（Instruments／Workspace／Utilities） | **仍成立** |
| 04 · 方法與故事 | **改由漫畫與 Blog 承載**，而非另寫一套方法論頁面 |

原構想的三項待決，本輪的處理：

| 前一輪待決 | 本輪狀態 |
|---|---|
| 方法入口指向哪裡 | 方向已定：漫畫與 Blog；實際連結配置**尚未決定** |
| 第一篇案例寫哪一個 | 改為「第一批展示的漫畫內容」，**尚未決定** |
| 七項工具收攏到什麼程度 | **仍未決定**，但邊界已定：可發現性必須保留 |

# 四、目前首頁的事實（2026-09-20 實查）

供之後動手時對照，非構想內容：

- 實作在 `src/views/HomeView.astro`，**刻意不用共用的 `PlatformShell`**，自己一套極簡版面，因此**沒有上方導覽列**，只有右上角語言切換。
- 由上而下只有四塊：WTLab 字標 → 一句標語 → 「決策工具」7 張卡 → 「公用工具」1 張卡。
- 卡片不是寫死的：決策工具讀自註冊表（只列 `status: active` + `enabled`），公用工具全列（含「即將推出」）。
- **首頁目前沒有任何入口通往整合工作區、工作區、延續性、關於。**
- 站上**沒有**漫畫、Blog、Podcast 或方法論頁面；`/about` 是架構說明的佔位頁。

## Integrated Workspace 的真實狀態

首頁若要提供入口，狀態必須照實標示：**測試版・部分完成**——只顯示 Quick 模式的工作資料，計算仍在各工具內，資料是暫時的工作狀態，不是永久保存。詳見 [deployment.md](../deployment.md#prototype-resources--live-path-routed-in-production)。

# 五、邊界

- **不得把未完成的東西寫成已上線服務**——漫畫、Blog、Podcast、Phoenix 或其他 App 都一樣。
- 工具區的專業調性不隨首頁轉型改變；**不重做工具介面或計算邏輯**。
- 首頁轉型不得犧牲七項 Instruments 的可發現性。
- 不把 WTLab 改成個人履歷網站。

---

# 六、真要動手時的落地清單（尚未開始）

- 首頁是自己的極簡殼、沒有導覽列——新增入口要決定是加區塊還是改用 `PlatformShell`（後者會改變首頁既有的視覺定位，屬於獨立決定）。
- 所有新文案要同時進 `src/i18n/zh-TW.ts`、`src/i18n/en.ts` 與 `src/i18n/types.ts` 的 `Dictionary`，中英文案一起定。品牌語氣（詼諧、自嘲）在兩個語系要各自成立，不是直譯。
- 首頁卡片來自註冊表，改成群組入口等於改變資料來源的用法，要確認不會把「只列真的能用的」這條規則弄丟。
- 漫畫／Blog／Podcast 若要上站，各自需要內容來源與呈現方式的決定，目前都沒有。
