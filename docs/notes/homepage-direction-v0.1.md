## 一句話

輪椅哥品牌入口，透過漫畫呈現理念，並保留工具的快速入口。

```
輪椅哥 → 輪椅流（四格） → 漫畫 → 輪椅工具 → Blog／Podcast
```

# 一、已確認方向

## 1. 品牌定位

| 角色 | 定位 |
|---|---|
| **輪椅哥** | 品牌 IP 與視覺主角。英文名**定案為 `Wheelchair Bro`**（2026-09-21） |
| **輪椅流** | 核心理念——強調現實問題、韌性、容錯與持續校正。英文 `the Wheelchair Way` |
| **WTLab** | 輪椅哥的工具平台，承載實際工具與成果 |
| **創作者本人** | 提供真實經歷與個人風格，**但不把 WTLab 改成個人履歷網站** |

## 2. 首頁調整方向

- 從**工具陳列站**轉型為**輪椅哥的品牌入口**。
- 恢復早期小卡延續而來的詼諧、自嘲與漫畫風格。
- 可以大膽帶入創作者的個人語氣與特色。
- **「帶你飛，保證摔不死！」** 作為既有品牌精神。
- 協作理念透過角色、故事與成果呈現，**不另行包裝成 AI 教學平台**。

## 3. 內容與入口關係

| 內容 | 角色 |
|---|---|
| **漫畫** | 主要品牌內容，以生活白話與日常故事為主 |
| **輪椅工具** | WTLab 的核心實用成果 |
| **Blog** | 與漫畫互相導流 |
| **Podcast《行者自語》** | 輔助內容，可在網站提供播放，**不作為首頁主角** |

## 4. 工具區邊界

- 首頁可以大幅調整視覺個性。
- **進入工具區後，沿用現有專業、清楚的設計調性。**
- 保留七項 Instruments 的可發現性。
- 首頁應提供 Integrated Workspace 入口，並**如實標示其目前狀態**。
- **不因首頁轉型而重做工具介面或計算邏輯。**

# 二、實際做出來的（v0.2，2026-09-21 上線）

## 頁面結構（由上而下）

1. **Hero** — 輪椅哥、「帶你飛，保證摔不死！」、兩個行動（進工具間／先看漫畫）
2. **四格講完輪椅流** — 咦！／蛤？／靠北唷！／好，再來。對應現實問題、容錯、韌性、持續校正
3. **漫畫** — 四則，點圖滿版閱讀；每則另有連往 Jim's Talk 白話版的獨立連結
4. **輪椅工具** — 七項 Instruments＋工具庫＋Integrated Workspace＋公用工具
5. **Blog／Podcast** — Blog 四篇對應四則漫畫；Podcast 標示「準備中・還沒開錄」

## 實作方式

- `src/views/HomeBrandView.astro` 自成一套外殼，與工具頁的 `PlatformShell` 分開——品牌語氣只留在首頁。
- 元件在 `src/components/home/`（Hero、WheelchairFlow、Comics、Tools、BlogPodcast、Footer）。
- 圖片在 `public/brand/`，對外連結與篇目資料在 `src/platform/brand-content.ts`，文案全部走 i18n，中英文各自寫、不是直譯。

## 誠實邊界怎麼落實的

| 承諾 | 實作 |
|---|---|
| 工具不得寫死 | 七項 Instruments 由 `platformRegistry.getAvailable()` 產生；守則測試改指向實際渲染的 `ToolsSection.astro` |
| 工作區狀態要照實 | 用 `StatusTag` 讀目錄狀態顯示「測試版・部分完成」，並列出三點限制（只有 Quick 模式資料／計算在各工具內／資料是暫存） |
| 不得把未完成的包裝成上線 | 漫畫區明寫「站上漫畫頁尚未上線」；Podcast 只有文字說明，**沒有播放器** |
| 工具區調性不變 | 工具卡片沿用既有樣式與資料規則，未動計算、schema 或 API |

## 手機動態（桌機不套用，系統開啟「減少動態」時全部停用）

| 效果 | 參數 |
|---|---|
| Hero 手寫字視差 | 位置 `left: 48%`／寬 `68%`／傾斜 `15deg`；停止點由版面實測（標題頂端往下 62px）；速度 1.35，約捲 110px 定位 |
| 區塊捲動淡入 | IntersectionObserver，只播一次，同區塊內錯開 70ms；**4 秒後若一個都沒顯示就自動撤掉效果**——內容看不到比沒有動畫嚴重 |

## 過程中學到、值得記住的

- **旋轉會帶歪位移。** CSS 合成順序是先 `rotate` 後 `transform`，所以用 `transform` 做位移會沿著傾斜後的軸線跑。改用獨立的 `translate` 屬性（排在 `rotate` 之前）才會是垂直。
- **量測要扣掉自身效果。** 停止點若用旋轉後的外框計算，角度一改位置就跟著跑；先還原再量才穩定。
- **iOS 的文字自動放大會放大版面問題。** 比視窗寬的區塊，WebKit 會放大其中文字，於是更寬——`text-size-adjust: 100%` 是根治，`min-width: 0` 讓欄位能縮是配套。
- **動畫要有失效時的退路。** 捲動淡入加了 4 秒保險，observer 沒觸發就整個撤掉。
- **預覽窗格被遮住時不會重繪**，`requestAnimationFrame` 和 IntersectionObserver 都不會跑，動態效果在那裡量不準——要在真實瀏覽器確認。

- 首頁轉型不得犧牲七項 Instruments 的可發現性。
